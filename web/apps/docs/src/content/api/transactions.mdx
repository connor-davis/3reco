# Transactions API

A transaction is a completed trade. Accepting a request makes one, and a business can also record a collection from a collector or a direct sale. All routes are under `/api` and need a signed-in user. You only see trades where you are the buyer or the seller, unless you are an admin or staff member, who can read every trade.

A transaction is:

```json
{
  "id": "...", "type": "c2b", "seller": { "id": "...", "name": "..." },
  "buyer": { "id": "...", "name": "..." }, "total_price": "812.50",
  "collection_day": "2026-11-05", "collection_date": null, "effective_at": "...", "created_at": "...",
  "invoice_number": "A1B2C3D4",
  "items": [{ "material_id": "...", "material_name": "PET Plastic", "weight": "125", "price": "6.50" }],
  "receipts": [{ "id": "...", "file_name": "...", "content_type": "image/png", "size": 1234, "uploaded_at": "..." }]
}
```

`type` is `c2b` (collector to business) or `b2b` (business to business). All money and weights are decimal strings.

## Read

| Method | Path | Returns |
|---|---|---|
| GET | `/api/transactions/` | Your trades (page: `cursor`, `limit`; `all=true` returns up to 1000 as a plain array) |
| GET | `/api/transactions/purchases` | Trades where you are the buyer |
| GET | `/api/transactions/sales` | Business-to-business trades where you are the seller |
| GET | `/api/transactions/:id` | One trade (participants, admins and staff) |

## Record

### `POST /api/transactions/collections`

A business records a purchase from one of its collectors. Each line's `price` may differ from the material's base price, higher or lower.

```json
{
  "collector_id": "...", "business_id": "...",
  "items": [{ "material_id": "...", "weight": "125", "price": "6.50" }],
  "collection_day": "2026-11-05"
}
```

**Returns:** `{ "transaction_id": "..." }`

### `POST /api/transactions/sales`

A direct business-to-business sale: `{ "business_id": "...", "items": [...] }`. **Returns:** `{ "transaction_id": "..." }`

Weights and prices match `^\d{1,12}(\.\d{1,6})?$`. A trade has at most 100 lines and no repeated material.

## Invoice and receipts

| Method | Path | What |
|---|---|---|
| GET | `/api/transactions/:id/invoice` | The PDF invoice, as a download |
| POST | `/api/transactions/:id/receipts` | Upload a receipt: multipart field `file`, PNG or JPEG, up to 5 MiB, at most five per trade |
| GET | `/api/transactions/:id/receipts/:receipt_id` | Download a receipt |
| DELETE | `/api/transactions/:id/receipts/:receipt_id` | Remove a receipt; staff can remove only receipts they added, while admins can remove any |

The buyer, a business seller, admins and staff can attach up to five receipts once the trade is complete. Other callers get `404`; a pending trade or a receipt already attached to the trade gets `409 conflict`. A missing file or invalid image gets `400`.

Live updates: `transactions:<your user id>`.
