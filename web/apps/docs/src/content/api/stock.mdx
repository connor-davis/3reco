# Stock API

Stock is the physical material a user holds: a material, a weight and a price per kg. Listed stock shows on the market. All routes are under `/api`.

A stock item is:

```json
{
  "id": "...", "owner_id": "...", "material_id": "...", "material_name": "PET Plastic",
  "weight": "120.5", "available_weight": "100", "price": "6.50", "base_price": "6.00",
  "is_listed": true, "image_url": "/api/stock/.../image?v=...", "created_at": "..."
}
```

Weights and prices are decimal strings. `available_weight` is `weight` minus what open offers have reserved, never below zero.

## Read

### `GET /api/stock`

Your own stock, a page with `cursor` and `limit`. `all=true` returns a plain array.

**Access:** signed in

### `GET /api/stock/:id`

One item. The owner can always read it; anyone else only while it is listed. Otherwise `404 not_found`.

## Change

### `POST /api/stock`

```json
{ "material_id": "...", "weight": "120.5", "price": "6.50", "is_listed": true }
```

**Returns:** `{ "id": "..." }`

`base_price` is the material's default price. It is a starting suggestion, not a floor: any positive price with up to 2 decimals, up to the maximum, is accepted, on create and on update. The app fills the default when a material is picked and warns when the price is lower. To add a photo, create the stock first, then `POST /api/stock/:id/image` with the returned `id`.

### `PATCH /api/stock/:id`

Any of `weight`, `price`, `is_listed`. Left out means unchanged. **Returns:** `{ "ok": true }`

Listing or unlisting updates the market live without adding a notification to the owner's bell.

### `DELETE /api/stock/:id`

**Returns:** `{ "ok": true }`

You can only change or delete your own stock. Someone else's id gets `404 not_found`.

## Photos

Up to 8 photos per stock item; the first is the cover. A stock item returns `photos` (`[{ "id", "url" }]`, in order) and `image_url` (the cover, empty when none). Marketplace listings return `image_urls` and `image_url`. URLs are versioned. The internal object key is never returned.

### `POST /api/stock/:id/photos`

Multipart form data with a `file` field. PNG, JPEG and WEBP, detected from the bytes, up to 2 MiB. Empty, oversized or unsupported images return `400`. A ninth photo returns `400`.

**Access:** any member of the owning business. Anonymous callers get `401`; another business's id gets `404 not_found`.

**Returns:** the updated stock item.

### `PUT /api/stock/:id/photos/order`

Body `{ "ids": ["...", "..."] }`: every photo id of the item, in the new order. A missing, extra or repeated id returns `400`. Same access. **Returns:** the updated stock item.

### `DELETE /api/stock/:id/photos/:photo_id`

Same access. **Returns:** the updated stock item. The file is removed after commit. Deleting stock or erasing its owner's account removes all its photos after commit.

### `GET /api/stock/:id/photos/:photo_id`

Streams one photo. `GET /api/stock/:id/image` still works and streams the cover. The business's own members and staff can read while unlisted or empty. Everyone else can read only while the stock is listed, weight is above zero, and the seller is a verified business that has not been removed. Otherwise `404 not_found`.

**Cache-Control:** `private, max-age=60`.

Marketplace listing responses also include `image_url` and `seller_avatar_url` (the business's existing profile picture).

Live updates send a `stock` change to the owner when stock, its photo or its holds change. Listed photos also send a `listing` change to everyone signed in. Photo changes also send a `stock` change. Business logo changes send a `listing` change too.
