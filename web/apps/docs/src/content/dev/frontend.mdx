# Frontend Guide

The 3rEco web app is a React 19 SPA built with Vite and TanStack Router, in `web/apps/app`. It talks to the Go API through one client and gets live data over one WebSocket.

## Directory Structure

```
src/
├── routes/        file-based routes (TanStack Router)
├── components/    shared components; ui/ holds the shadcn primitives
├── hooks/         custom hooks
├── lib/
│   ├── api/       the API client, types and one hook file per resource
│   ├── live/      the WebSocket connection and the useLiveEvents hook
│   └── auth/      the signed-in user and access checks
└── main.tsx       entry point
```

## Path Alias

All imports use `@/`, which resolves to `src/`:

```typescript
import { cn } from '@/lib/utils'
import { Button } from '@/components/ui/button'
```

## Talking to the API

Calls go through `src/lib/api/client.ts`, which sends cookies (`credentials: "include"`), reads the JSON error body and throws a typed error. Each resource has hooks built on TanStack Query, and the hooks return the API's own types:

```typescript
const { data, fetchNextPage, hasNextPage } = useStock()   // a paged list
const create = useCreateStock()                           // a mutation
```

Lists are paged with a cursor: pass back `next_cursor` unchanged. Money and weights are decimal **strings** end to end: never turn them into floats.

In development Vite proxies `/api` (and the WebSocket) to the Go server on `:8180`, so the app needs no environment variables.

## Live data

The signed-in shell calls `useLiveEvents` once. It opens one socket and subscribes to nothing; the server decides who hears each change. Each `changed` event has a `kind` and an `id`, and the matching queries are invalidated (at most once per key every 300 ms). After a reconnect everything is invalidated. See [Notifications Pattern](/docs/dev/notifications).

## Routing

Routes are files under `src/routes/`. `routeTree.gen.ts` is generated by the router plugin: never edit it by hand.

```tsx
export const Route = createFileRoute('/stock')({
  component: StockPage,
})
```

A route that needs a signed-in user or a role checks it with the access helpers (`src/lib/auth` for the user, `src/lib/access.ts` for the rules). The server checks again on every request, so a hidden button is never the only protection.

## Components

- Use the shadcn primitives in `components/ui` and the shared components before making new ones.
- Add a primitive with `npx shadcn@latest add <component>`.
- Tailwind CSS v4 comes in through the Vite plugin; there is no `tailwind.config.js`.
- Every page works in light and dark.

## Commands

```bash
npm run dev     # Vite alone
npm run build   # tsc -b && vite build, into dist/
npm run lint    # tsc -b && eslint . && prettier --check .
npm test
```

From the repo root, `task dev` runs the API and Vite together, and `task check` runs everything.
