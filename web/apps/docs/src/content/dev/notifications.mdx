# Notifications Pattern

3rEco tells people about events with rows in the `notifications` table. Postgres sends a `NOTIFY` when a row is inserted, the realtime hub pushes a small event over the WebSocket, and the web app refetches its notification list.

## How It Works

1. A service does something the user should know about and inserts a notification for the right `user_id`, **inside the same transaction** as the change. If the transaction rolls back, so does the notification.
2. The `notifications` trigger sends `notifications:<user_id>` on the `threereco_changes` channel.
3. The hub forwards `{"type":"changed","topic":"notifications:<user_id>","id":"<notification id>"}` to that user's open sockets.
4. The app invalidates its notification queries and refetches.

The event never carries the notification itself, so a client that missed an event loses nothing: the next fetch has it.

## Notification Types

| Type | Sent when |
|---|---|
| `request_received` | A buyer sends a request to a seller |
| `request_accepted` | An offer is accepted |
| `request_rejected` | A seller rejects a request, or a buyer declines an offer |
| `request_cancelled` | A buyer cancels, or a seller withdraws an offer |
| `message_received` | A new message arrives in a request chat |
| `stock_listed` | A stock line is listed on the market |
| `stock_unlisted` | A stock line is taken off the market |

Each notification has `id, type, title, body, link, read, created_at`. `link` is an app route such as `/market/<id>` or `/market/incoming`.

## Routes

| Method | Path | What it does |
|---|---|---|
| GET | `/api/notifications/` | The feed, newest first, with a cursor |
| GET | `/api/notifications/unread-count` | `{count}` for the bell badge |
| PATCH | `/api/notifications/:id/read` | Mark one read |
| POST | `/api/notifications/read-all` | Mark all read |
| DELETE | `/api/notifications/:id` | Dismiss one |
| DELETE | `/api/notifications/` | Dismiss all |

Notifications and carts older than 90 days are deleted every hour by the privacy clean-up.

## Adding a type

1. Add the type to the list in `internal/services/notifications/notifications.go`.
2. Call the notifications service from the service that causes the event, in the same transaction.
3. Add a test that checks the right person gets it and nobody else does.

<Callout type="tip" title="Keep the body short">
  The body shows in a compact panel. Keep it under 120 characters and say what action to take.
</Callout>
